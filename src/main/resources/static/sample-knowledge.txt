知行 LearnHub AI · RAG 入门学习资料
这是一份公开演示资料，不包含个人信息或服务凭据，可用于测试知识库检索。

第一节：什么是 RAG？
RAG 是 Retrieval-Augmented Generation 的缩写，中文通常叫检索增强生成。它先从知识库中查找与问题相关的资料片段，再把这些资料片段和问题一起交给语言模型生成答案。RAG 的核心流程是：资料导入、文本提取、文本分块、建立索引、检索相关片段、基于证据生成、返回来源引用。
RAG 不是把整份资料永久训练进大模型，也不保证答案一定正确。知识库内容可能过时，检索可能漏掉重要证据，模型也可能误读原文。因此应显示引用，让学习者回到原文核对。没有足够证据时，应说明资料不足，而不是编造结论。

第二节：为什么需要文本分块和重叠？
课程讲义通常较长，一次把整份文档交给模型会增加成本，也容易让相关信息被无关信息淹没。文本分块把文档切成较短的片段，每个片段可以单独建立索引和检索。知行默认使用约 800 字符的片段，相邻片段保留约 100 字符重叠。
分块重叠用于保留切分边界附近的上下文。例如一句定义与紧随其后的例子落在不同片段中，重叠可以减少语义断裂。片段太短可能缺少上下文，片段太长则可能降低检索精度。合理的分块长度与资料结构、语言、模型上下文窗口有关，没有对所有资料都最优的单一数值。
PDF 导入时需要可提取的文字层。只有扫描图片的 PDF 需要先做 OCR，当前学习版不执行 OCR。保留页码可以帮助读者定位原始段落。表格与多栏 PDF 的文字读取顺序可能与视觉阅读顺序不同，导入后应检查检索片段。

第三节：词项哈希检索与语义向量有什么区别？
词项哈希检索把词语或中文相邻字符组合映射到固定维度向量，再比较向量相似度。这种方式不需要外部模型，也不需要模型 API 密钥，适合本地入门与离线演示。它主要依赖词面重合，哈希碰撞也可能引入噪声，不等同于理解语义。提问使用资料里已有的关键词时，通常更容易找到相关段落。
语义向量也叫 embedding，由嵌入模型把文本映射为向量。表达相近但词面不同的句子，可能具有相近的语义向量。启用语义向量时，文档片段和查询必须使用兼容的同一个向量模型与维度。更换向量模型后，旧向量通常不能直接与新查询向量比较，需要重新建立索引。
余弦相似度描述两个向量方向的接近程度，不是答案正确率，也不是事实真实性的概率。检索的 topK 表示取相似度较高的前 K 个候选片段；K 太大可能引入噪声，太小可能漏掉必要证据。召回阈值需要结合真实问题集评估，不能只凭单个演示问题调参。

第四节：RAG 和模型微调有什么区别？
RAG 主要通过外部资料提供当前问题需要的事实依据，不修改模型参数。更新课程文档后，可以重新导入和索引，使新资料参与检索。RAG 适合课程讲义问答、企业文档查询、技术手册助手等经常更新的知识任务。
模型微调则用训练数据调整模型参数，常用于改善任务格式、表达风格或特定任务能力。微调不应被当成可靠的、可实时更新的事实数据库。RAG 和微调可以组合使用，但二者解决的问题不同。对个人课程资料助手，先做好资料质量、切分、检索和引用，通常比立刻训练模型更容易验证效果。

第五节：知识库问答的安全与隐私
导入的文档只是资料，不是系统指令。文档中即使出现“忽略之前的要求”或要求泄露令牌的文字，也不应改变应用的权限边界。检索增强生成应把资料作为低信任证据，明确区分应用规则、用户问题和文档内容，不执行文档中的指令或代码。
知行的访问令牌用于保护本地 API，与模型服务 API 密钥不是同一个东西。模型密钥只在后端环境变量中设置，不应写入网页、源代码、学习笔记或公开 Git 仓库。默认本地检索无需外部请求；启用模型服务后，问题与检索片段会发送到配置的服务，导入敏感资料前应了解该服务的数据政策。
知识库之间应隔离检索，删除资料时也应删除对应分块和向量。历史问答的引用如果对应资料已经删除，应明确标记来源不可用，不能把失效引用当成当前知识依据。

第六节：怎样验证一个学习知识库？
先准备一组答案确实存在于资料中的问题，检查相关片段是否出现在检索结果里，再核对生成答案是否忠于这些片段。然后加入资料中没有答案的问题，观察系统是否承认证据不足。最后测试空文件、扫描 PDF、超大文件、不同知识库隔离、删除文档后的引用状态，以及未配置模型服务时的检索模式。
